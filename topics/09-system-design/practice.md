# Practice Guide

## Goal
Turn requirements into an architecture and defend every component.

## Exercises
1. Estimate traffic/storage for a service with 1M daily users.
2. Design a URL shortener and explain ID generation, cache, database, and failure handling.
3. Design notifications with queues, retries, idempotency, and DLQ.
4. Design large-scale RAG and identify retrieval/model bottlenecks.

## Deliverable
Create an architecture diagram, API list, rough capacity table, failure matrix, and one ADR explaining a major trade-off.

## Interview drill
Explain your design in 10 minutes, then answer: “What breaks first?”, “How do you scale it?”, and “What would you remove if cost doubled?”
